# Scope fidelity

Implement the requested behavior, content, or development tooling. Routine implementation choices and verification inside that request are authorized; complete them without repeated permission questions.

Preserve existing product copy, UI, assets, and behavior outside the request. Do not add features, rewrite content, fix unrelated app bugs, or implement blueprint items just because they are mentioned in documentation. Ask before expanding scope when a separate improvement would materially help. Record an observed issue with evidence rather than silently implementing it.

Preserve pre-existing staged/unstaged changes and secrets. A shared checkout's dirty files are not automatically task-owned. Instructions and approval already supplied by the user take precedence over inferred restrictions in a playbook.
